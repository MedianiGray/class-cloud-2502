网页与文档的关系

这套网页是「索引」，不是「仓库」。GitHub Pages 上只有班级名册和链接，没有任何文档正文、附件或成绩数据。真正的访问控制发生在 WPS：成员点开链接后，WPS 会先校验他的账号与权限，没权限的人看到的只是一张「无权访问」的提示。因此就算网页链接被转发出去，文件本身也不会泄露。

这也是这套结构能长期用的原因：调整权限不用改代码，在 WPS 里点几下就行；网页不需要维护数据。

部署与维护

本文件是单文件静态页，不依赖任何服务器与数据库。上传到 GitHub 仓库并开启 Pages 即可对外访问。

一、挂到 GitHub Pages

01
新建一个仓库（如 class-cloud-2502），把本文件上传到仓库根目录。
02
重命名为 index.html。GitHub Pages 只把 index.html 当作默认首页；不改名则需带完整文件名访问。
03
进入仓库 Settings → Pages，Source 选 Deploy from a branch，分支选 main、目录选 / (root)，保存。
04
等 1–2 分钟，访问 https://你的用户名.github.io/仓库名/。这就是班级的固定入口，可以做成二维码发到班群。
05
后续更新只需在网页上修改仓库里的 index.html 并提交，Pages 会自动重新发布，链接不变。

二、改口令与名册

页面里的所有数据都写在文件末尾的脚本区，两处即可维护：

// 1) 访问口令 const GATE_CODE = "2502"; // 2) 成员名册：改姓名、换文件夹链接、加人减人 const MEMBERS = [ { no:"201", name:"王苏子明", slug:"ctWvsvDFbsPW" }, ... ];

成员链接只取 WPS 文件夹地址末尾那段（如 kdocs.cn/folder/ctWvsvDFbsPW 里的 ctWvsvDFbsPW）。新增同学照抄一行、改姓名学号链接即可，其余排序、检索、统计会自动重算。

三、内嵌预览为什么可能空白

「尝试内嵌预览」是在页面里用 iframe 打开 WPS 链接。WPS 与多数校内系统都设置了禁止外部页面嵌套的安全策略，这时预览区会显示拒绝或空白——这是对方的安全设置，不是页面故障，也无法绕过。遇到这种情况点「在 WPS 中打开」，浏览器新标签页里正常访问。

所以本页把内嵌预览定位为「顺手看一眼」，真正的阅览与编辑始终在 WPS 里完成，这样权限校验也始终由 WPS 负责。

四、公开仓库的隐私问题

GitHub Pages 免费版只能挂公开仓库，任何人都能打开这个网址、也能在仓库里看到源码。所以名册里不存完整学号：45 人的学号一律只保留后三位，完整学号只存在于班级 WPS 云库。除此之外还有两层降低暴露的手段：noindex 阻止搜索引擎收录、口令门挡住随手点开的人——这两层都不是真正的安全措施，只是降低被随手翻到的概率。

如果还想更稳：① 用学校服务器或教育网空间托管（可做真实鉴权）；② 名册只保留「序号 + 姓名」，连后三位也不要。文档本身的权限是安全的，因为文件都在 WPS 里。

五、给评奖评优留的位置

这套结构先把「材料归位」做掉，评优就不靠临时翻聊天记录。建议每学期在共享库里固定四类目录：01 通知归档 / 02 集体荣誉 / 03 个人材料 / 04 申报汇总；个人证书扫描件各人放进自己的独立文件夹。学期末班委只需打开总目录，逐人核对即可，不必再逐个私聊收材料。
